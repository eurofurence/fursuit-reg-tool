# Parity Checklist: /admin -> /manage

Tick list for every phase PR and again for the cutover PR. Every line is either covered by a test in
`tests/Feature/Manage/` (name the test when you tick it), or marked `[~]` with a pointer to
`rebuild-plan.md`. Nothing ships unticked.

Derived line by line from [`current-filament-features.md`](./current-filament-features.md), in that
document's order. Do not edit this file to make it pass; edit the code.

## Cutover status

Part 5 of [`rebuild-plan.md`](./rebuild-plan.md) has landed. The Inertia panel is the only panel.

Read `/manage` below as `/admin`: the panel was built behind that path and moved to `/admin` at
cutover (plan Part 5 step 14). The URL, the route-name prefix `admin.` and the redirect from
`/admin-legacy` are the final shape; the internal names (`App\Support\Manage`,
`resources/js/Components/Manage/`, `manage.css`, the `manage.event_id` session keys) deliberately
did not move, so the wording in the lines below still matches the code it points at.

Verified at cutover:

- No Filament package, provider, resource, page, widget, view or stylesheet remains. `composer.json`
  no longer requires `filament/filament` or `flowframe/laravel-trend`, there is no `filament:upgrade`
  script, and `composer validate` / `composer install --dry-run` resolve against the committed lock.
  What survives the grep is prose: comments and test names that say what the old panel did, which is
  the parity record this document exists to preserve.
- No `manage.*` route name survives; 133 `admin.*` names resolve with no duplicate name and no
  duplicate method+URI inside the panel group (`AccessTest`).
- `/admin-legacy` and `/admin-legacy/{any deep link}` answer `301 -> /admin`.
- The rail renders all 18 items across all 9 groups. `Navigation::item()` drops any entry whose
  route is missing, so this is the check a missed rename would have failed silently
  (`ListEnvelopeTest`: the sidebar carries every module registered so far, plus the enumeration run
  at cutover: Dashboard, Events, Badges, Fursuits, Special Codes, Checkouts, Machines, Staff,
  SumUp Readers, TSE Clients, Printers, Print Jobs, Print Batches, Users, PDF Generator,
  Badge Preview, Settings, DB Service).
- Every parameterless `admin.*` GET route answers 200, or 302 where it is a redirect by design
  (`admin.fursuits.review`, `admin.tools.pickup-booths-moved`).
- Fifteen list shapes were driven through the real partial visit (`X-Inertia` plus
  `X-Inertia-Partial-Data: rows,meta,filters,sort,search`) with the row set asserted to move:
  events, badges, fursuits, users, special codes, machines, staff, SumUp readers, TSE clients,
  printers, print jobs, print batches, batch cards, checkouts and checkout items (`ListEnvelopeTest`,
  `FilterDriveTest`, `ToolbarDriveTest`).
- There is no development login bypass in `routes/web.php`. The two `local`-only routes left there
  (`dev.ui.parity`, `dev.ui.error`) render Vue pages and authenticate nobody.

Legend:

- `[ ]` parity behaviour, must be reproduced and tested.
- `[x]` done, name the test.
- `[~]` deliberately changed. The pointer names the `rebuild-plan.md` item that authorises it.
  A `[~]` line is ticked by confirming the *new* behaviour, not the old one.

Filament default copy referenced below, verbatim, as the framework renders it:
`DeleteAction` heading `Delete :label`, description `Are you sure you would like to do this?`,
submit `Delete`, cancel `Cancel`, success toast `Deleted`;
`DeleteBulkAction` trigger `Delete selected`, heading `Delete selected :label`, same description
and submit; a bare `requiresConfirmation()` uses the action's own label as the heading, the same
description, and submit `Confirm`.
